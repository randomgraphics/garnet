# Assignment: Dynamic GPU Buffer Upload — Frame-in-Flight Ring Buffering

## Goal

Add an `UploadBuffer` **action** to the RDG that lets app code upload per-frame dynamic
data (UBOs, per-frame constants, etc.) to the GPU efficiently and safely, without ever
calling `Buffer::setContent()` directly, and without stalling the CPU waiting for the GPU
to finish the previous frame.

"Done" means:
  - `UploadBuffer::create()` allocates N (2) ring-buffered host-coherent VkBuffers.
  - `execute(args)` picks the next safe slot (checking the slot's SubmissionID before
    writing), copies the CPU data into it, and records the slot as the "current" one.
  - After each GPU submit, the `SubmissionID` is stored into the slot so the next time
    that slot is reused the implementation knows when the GPU is truly done with it.
  - `currentBufferView()` returns a `GpuResourceView` pointing to the current slot's
    buffer; draw actions bind this view in their resource table.
  - `SharedShaderConstants` is refactored to use `UploadBuffer` actions internally
    (camera UBO + lighting UBO), so app code still just calls `setViewInformation()`.
  - The `waitForIdle()` full GPU drain is removed from the per-frame hot path; the CPU
    and GPU can pipeline N frames simultaneously.

## Design Overview

### Core idea: app only touches actions, never raw GPU buffers directly

```
// One-time setup
auto cameraUpload = UploadBuffer::create(db, "camera-ubo", {.gpu=gpu, .size=sizeof(GlobalCameraUBO)});

// Each frame — build submission
submission.add(cameraUpload, UploadBuffer::A::make(&cameraUbo, sizeof(cameraUbo)));
submission.add(draw, drawArgs);   // drawArgs.resources[0][0][0] = cameraUpload->currentBufferView()
```

The RDG guarantees `cameraUpload` runs before `draw` (explicit insertion order + RW-list
dependency declaration).  The ring-buffer inside `UploadBuffer` makes sure the CPU never
writes into a slot the GPU is still reading.

### Ring-buffer contract

  N = 2  (constant `MAX_UPLOAD_SLOTS`)
  slot index i = (frame_submission_counter++) % N

  Before writing slot i:
    if mSlots[i].submissionId is not done yet → wait (rare: only when N frames pile up)
  After writing slot i:
    mCurrentSlot = i
  After GPU submit:
    mSlots[i].submissionId = <SubmissionID from this frame>

### Where SubmissionID comes from

`rapid_vulkan::CommandQueue::submit()` returns a `SubmissionID`. The
`CommandBufferManagerVulkan` already has all SubmissionIDs in its map after submit.
A new hook `SubmissionContextVulkan::notifyUploadBuffers(SubmissionID)` will iterate all
`UploadBuffer` actions registered during the current submission and call their
`notifySubmission(id)`.

### How draw actions get the right buffer view

`UploadBuffer::currentBufferView()` returns `GpuResourceView` with the slot's `Buffer`
artifact.  The app calls this AFTER adding the upload action to the submission (so the
slot is already chosen) and BEFORE adding the draw action.

### SharedShaderConstants integration

`SharedShaderConstantsVulkan` owns two `UploadBuffer` actions (`mCameraUpload`,
`mLightingUpload`).  On `setViewInformation()` / `setFrameInformation()` it packs the
CPU-side structs.  A new `prepareSubmission(Submission&)` method adds both upload actions
to the submission with the current packed data, and updates the descriptor set views.

### Removing waitForIdle

Currently `CommandBufferManagerVulkan` drains all queues after every submission — this
makes CPU and GPU serial.  Once every uploaded buffer has its own per-slot SubmissionID
guard and command buffers are recycled per-slot, the full drain can be replaced by a
per-slot "wait if and only if slot is not yet free" check.

    - Members in UploadBufferVulkan:
        struct Slot {
            rapid_vulkan::Ref<rapid_vulkan::Buffer> vkBuffer;
            rapid_vulkan::CommandQueue::SubmissionID submissionId;

        call `rapid_vulkan::CommandQueue::wait(mSlots[next].submissionId)`.

    Verify: unit test — execute() twice in a row without submit; second call picks slot 1
            and does NOT wait (submissionId is still empty → no wait path).
    Commit: "rdg(upload): implement execute() with ring-buffer selection (Phase 2.2)"

  Task 2.3: notifySubmission() — record SubmissionID for current slot

        stores `id` in `mSlots[mCurrentSlot].submissionId`.
    Verify: unit test — after notifySubmission(), mSlots[mCurrentSlot].submissionId == id.
    Commit: "rdg(upload): implement notifySubmission() (Phase 2.3)"

  Task 2.4: currentBufferView()
