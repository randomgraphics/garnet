# Assignment: Dynamic GPU Buffer Upload — Frame-in-Flight Ring Buffering

---

## Goals

### 1. Efficiency

  1.a  No CPU-GPU sync point unless absolutely necessary.
       The ring-slot / SubmissionID model enforces this: the CPU only waits when it is
       about to overwrite a slot the GPU is still reading — an event that should be
       extremely rare with N=2 slots and typical GPU/CPU cadence.  waitForIdle() is
       removed from the hot path entirely.

  1.b  Minimize memory copies — both CPU-side and GPU-side.
       Copies are expensive.  Every extra copy is counted and justified:

         HOST_VISIBLE_RING strategy (target: 1 copy or 0):
           Raw-pointer path  →  1 copy: user data → VkBuffer mapped memory (memcpy).
           Write-callback path → 0 copies: user constructs data directly in mapped memory.
           NO intermediate "blob" copy is allowed.  The A object must NOT contain a blob.

         DEVICE_LOCAL_STAGED strategy (target: 2 copies — unavoidable):
           Copy 1:  user data → host-visible staging VkBuffer (CPU side).
           Copy 2:  vkCmdCopyBuffer: staging → GPU-local VkBuffer (GPU side).
           The GPU-local buffer is in VRAM; GPU reads are fast.  The 2-copy cost is paid
           once per upload, not once per shader invocation — worthwhile for large or
           infrequently-changed data.

         Write-callback eliminates Copy 1 even in the staged case when the user can write
         structured data directly (e.g., filling a struct in-place in mapped staging mem).

### 2. Intuitive / Easy to use

  App code should never deal with VkBuffers, descriptor sets, ring indices, SubmissionIDs,
  or keepAlive lists directly.  The public RDG API hides all of that.

  Usage pattern for shared constants:

    // One-time setup (application init):
    auto sharedConsts = SharedShaderConstants::create(db, "scene", {.gpu = gpu});

    // Per frame:
    sharedConsts->setViewInformation(camera);
    sharedConsts->setDirectLightingInformation(lights);
    sharedConsts->prepareSubmission(submission);     // adds upload actions; updates descriptors

    submission.add(draw, drawArgs);                 // drawArgs use sharedConsts->getSet0Group()

  For direct use of UploadBuffer:

    // Setup:
    auto upload = UploadBuffer::create(db, "my-ubo",
                      {.gpu = gpu, .size = sizeof(MyUBO), .strategy = Strategy::HOST_VISIBLE_RING});

    // Per frame (raw pointer — 1 copy):
    submission.add(upload, UploadBuffer::A::make(&myUbo, sizeof(myUbo)));
    drawArgs.resources[0][0][0] = upload->currentBufferView();

    // Per frame (write callback — 0 copies):
    submission.add(upload, UploadBuffer::A::make([&](void * dst, uint64_t cap) {
        new(dst) MyUBO(myUbo);   // in-place construct directly into mapped GPU memory
    }));

### 3. Extensibility

  The ring-slot / SubmissionID / keepAlive model must support the following future
  extensions without a redesign:

  3.a  Per-draw dynamic-offset UBO (Vulkan dynamic buffer offset):
       Instead of one UBO per draw call (too many descriptor bind calls), all per-draw
       payloads for a frame are sub-allocated from a single large ring-slot buffer.
       Each draw call uses a different dynamic offset into that buffer.
       This maps to a "suballocating upload pool" that shares one VkBuffer across many
       draws with increasing offsets.  The ring-slot lifecycle and submissionId tracking
       are identical; only the allocation scheme differs.
       → Plan: introduce a UploadPool artifact/action in a follow-up assignment.
         UploadBuffer can serve as the single-allocation degenerate case.

  3.b  Streaming texture uploads (video playback etc.):
       Per-frame texture uploads need the same two-phase (CPU → staging → GPU image) model
       as DEVICE_LOCAL_STAGED, plus VkImage layout transitions instead of buffer barriers.
       The slot / submissionId / keepAlive model applies directly.
       → Plan: introduce UploadTexture action in a follow-up assignment.
         Its Slot struct is identical except vkBuffer → vkImage + layout tracking.

  Design rule: isolate the ring-slot lifecycle (wait → release keepAlive → write → record
  keepAlive → advance → notifySubmission) into a reusable helper so UploadBuffer,
  UploadPool, and UploadTexture all share the same machinery without duplicating it.

## Design

### A. Core abstraction: GpuUploadSlot (shared helper, not a public API)

Used internally by UploadBufferVulkan (and later UploadPoolVulkan, UploadTextureVulkan).

  struct GpuUploadSlot {
      rapid_vulkan::CommandQueue::SubmissionID submissionId;
      DynaArray<AutoRef<RefCounted>>           keepAlive;

      // Returns true if slot is available (GPU done or never used).
      bool isReady(/* CommandQueue & q */) const;

      // Wait until slot is ready (blocks only if submissionId not yet done).
      void waitUntilReady(rapid_vulkan::CommandQueue & q);

      // Release keepAlive, reset submissionId.  Must be called after waitUntilReady().
      void recycle();

      // Record a resource to keep alive until this slot's GPU work is done.
      void addKeepAlive(AutoRef<RefCounted> ref);

      // Called after GPU submit.
      void notifySubmission(rapid_vulkan::CommandQueue::SubmissionID id);
  };

UploadBufferVulkan owns N GpuUploadSlots.  Each slot also owns its backing VkBuffer(s).

### B. UploadBuffer::A — no blob, write directly to GPU memory

  struct A : public Arguments {
      // --- Set exactly one of the following ---

      // Raw-pointer path: backend calls memcpy(dst, data, dataSize).  1 copy.
      // Pointer NOT retained past execute().
      const void * data     = nullptr;
      uint64_t     dataSize = 0;

      // Write-callback path: backend calls writeFn(mappedPtr, slotCapacity).  0+ copies.
      // writeFn is called synchronously inside execute(); it need not outlive execute().
      std::function<void(void * dst, uint64_t capacity)> writeFn;

      static AutoRef<A> make(const void * data, uint64_t size);
      static AutoRef<A> make(std::function<void(void*, uint64_t)> fn);

      void addToReadWriteList(ArtifactReadWriteList&) const override;
  };

Note: there is NO blob field.  Data is written directly into mapped VkBuffer memory
during execute().  This keeps HOST_VISIBLE_RING at 1 copy (raw) or 0 copies (callback).

### C. HOST_VISIBLE_RING — execute() flow

  struct Slot : GpuUploadSlot {
      rapid_vulkan::Ref<rapid_vulkan::Buffer> vkBuffer;  // host-coherent, preallocated
  };

  execute(args):
    uint32_t next = (mCurrentSlot + 1) % MAX_UPLOAD_SLOTS;
    mSlots[next].waitUntilReady(queue);   // wait only if GPU still reading slot
    mSlots[next].recycle();               // drop old keepAlive; no user data to drop
    {
        Buffer::Map<uint8_t> m(*mSlots[next].vkBuffer);
        if (args->writeFn)  args->writeFn(m.data, mSize);
        else                memcpy(m.data, args->data, args->dataSize);
    }
    // No user data to add to keepAlive — data lives in vkBuffer which owns itself.
    mCurrentSlot = next;

  keepAlive note: for HOST_VISIBLE_RING the slot's vkBuffer is preallocated and always
  owned by the Slot — no transient resource to track.  keepAlive is empty per-slot.

### D. DEVICE_LOCAL_STAGED — execute() flow (future Phase 2.5)

  struct StagingSlot : GpuUploadSlot {
      rapid_vulkan::Ref<rapid_vulkan::Buffer> stagingVkBuffer;  // host-visible, preallocated
  };

  Members:
      rapid_vulkan::Ref<rapid_vulkan::Buffer> mGpuBuffer;  // device-local, single buffer
      StagingSlot mStagingSlots[MAX_UPLOAD_SLOTS];
      uint32_t    mCurrentStaging = MAX_UPLOAD_SLOTS - 1;

  execute(args):
    uint32_t next = (mCurrentStaging + 1) % MAX_UPLOAD_SLOTS;
    mStagingSlots[next].waitUntilReady(queue);
    mStagingSlots[next].recycle();
    {
        Buffer::Map<uint8_t> m(*mStagingSlots[next].stagingVkBuffer);
        if (args->writeFn)  args->writeFn(m.data, mSize);
        else                memcpy(m.data, args->data, args->dataSize);
    }
    // Record GPU-side copy and barrier into current command buffer:
    vkCmdCopyBuffer(cmdBuf, stagingVkBuffer, mGpuBuffer, ...);
    vkCmdPipelineBarrier(cmdBuf, TRANSFER_WRITE → UNIFORM_READ, ...);
    // stagingVkBuffer must live until GPU copy completes:
    mStagingSlots[next].addKeepAlive(wrap(mStagingSlots[next].stagingVkBuffer));
    mCurrentStaging = next;

  currentBufferView() → mGpuBuffer (the single GPU-local buffer, not the staging slot).

### E. SubmissionID plumbing

  SubmissionContextVulkan holds:
      DynaArray<UploadBufferVulkan*> activeUploads;  // reset each submission

  UploadBufferVulkan::execute() registers this into activeUploads.

  After CommandQueue::submit() returns SubmissionID:
      for (auto * ub : ctx.activeUploads) ub->notifySubmission(id);

  UploadBufferVulkan::notifySubmission(id):
      mSlots[mCurrentSlot].notifySubmission(id);   // delegates to GpuUploadSlot

### F. currentBufferView()

  HOST_VISIBLE_RING: → GpuResourceView of mSlots[mCurrentSlot].vkBuffer
                        type=UNIFORM, offset=0, size=mSize.
  DEVICE_LOCAL_STAGED: → GpuResourceView of mGpuBuffer (single device-local buffer).

  Called by app AFTER execute() runs (i.e., after adding upload action to submission,
  and before adding draw action).

### G. SharedShaderConstants integration

  Camera + lighting UBOs are small (240 + 784 bytes), updated every frame.
  → HOST_VISIBLE_RING is the right strategy.

  Members:
      AutoRef<UploadBuffer> mCameraUpload    (HOST_VISIBLE_RING, 240 B)
      AutoRef<UploadBuffer> mLightingUpload  (HOST_VISIBLE_RING, 784 B)
      GlobalCameraUBO       mPendingCamera   (CPU-side, updated on set*Information())
      DirectLightingUBO     mPendingLighting (CPU-side, updated on set*Information())

  prepareSubmission(Submission & s):
      s.add(mCameraUpload,   A::make(&mPendingCamera,   sizeof(mPendingCamera)));
      s.add(mLightingUpload, A::make(&mPendingLighting, sizeof(mPendingLighting)));
      mSet0Group->setResourceViews(0, 0, {mCameraUpload->currentBufferView()});
      mSet0Group->setResourceViews(1, 0, {mLightingUpload->currentBufferView()});

  This is the only call the app needs to make per frame for shared constants.

### H. waitForIdle removal

  After Phase 2 is done, every upload slot is guarded by its own SubmissionID.
  Command buffers will be tagged with SubmissionIDs too (Phase 6).
  The only wait left in the hot path is inside GpuUploadSlot::waitUntilReady(),
  which fires only when N frames pile up — a rare event in normal operation.
