## Goals

Implement fx2::bindless::SharedShaderConstants as the single long-lived owner of
the GPU data shared by the new bindless kernels. Additive only: existing GN::fx2
classes, shader contracts, and callers stay intact and keep working. Keep
gpu2::GpuContext named as-is. New public APIs are opaque contracts reached through
the monolithic GNfx2.h include; binding numbers, packing, allocators, and backend
details stay private.

SSC owns uniform and streaming stores only; callers manage the gpu2 heap separately.
Material chunk management is a built-in gpu2 heap extension, designed in
src/core/gpu2/README.md; it is not an FX2 storage subsystem.

R1 — Generic versioned uniform store (set 1, binding 1). Manages uniform records
by total byte size only; it does not know and must not interpret their internal
layout. Each update allocates a new, independently aligned range in long-lived
backing storage, so two updates are distinct GPU bytes rather than two writes into
one buffer. Update order is therefore independent of draw order, and this must
hold with distinct readback values:

    upload A -> upload B -> consumers B -> consumers A

The standard combined `SharedUniforms` structure is defined in the public
bindless SSC header. It remains a schema independent of the storage algorithms;
SSC continues accepting opaque byte records. A single 1,024-byte std140 UBO
holds frame fields, 16 direct lights and their active count, all legacy camera
fields, and an active sky-material index. Environment textures/calibration
belong to sky materials. No separate camera/light buffer is introduced.

R2 - Separate heap material consumption. Long-lived, read-only, non-uniform
records live in the gpu2 descriptor heap material buffer. Its contracts are
defined in src/core/gpu2/README.md. Callers provide that heap directly to
Raster/CnC; SSC neither owns nor requires it and implements no material
allocator. Kernels define schemas; callers retain referenced resources and
delay freeing chunks until consumers finish.

R3 — Streaming pool (set 1, binding 0). Holds one-time-use per-draw data that a
kernel wants the GPU to read but that is too large for push constants. Backed by
one or a few long-lived mappable buffers reused across draws and frames: no buffer
is created or destroyed per draw, and no CnC transfer is involved. allocate(size)
takes only a size and returns a CPU-writable block — an identifier plus an
ArrayView over the mapped range — and the caller fills the bytes. The consuming
raster or CnC payload owns the release, calling it when it completes or is
discarded so the range recycles within the pool. Shaders read the pool as an SSBO
through a per-draw offset encoded in the kernel's push constants. Keep pool
buffers persistently mapped for their lifetime when the backend and memory
allocation support it; otherwise map as needed. Map/unmap is not the mechanism for
synchronizing reuse with GPU consumers. Recorded or in-flight ranges must not be
overwritten. Flush non-coherent mapped ranges and establish host-write visibility
before shader consumption. The caller may release its source CPU input once it has
been copied into the mapped range.

R4 - Independent creation. SSC receives a gpu2::GpuContext directly. Creating
and using its uniform and streaming stores requires no descriptor heap.
Descriptor registration and heap-backed fallback resources belong to callers
or consuming kernels, outside the SSC storage contract.

R5 — Leases. A shared state, its upload work, unsealed recordings, and every
consuming payload retain a lease on the ranges they reference. Recycle storage
only after the final lease releases; upload completion alone is insufficient,
because a consumer may still be recorded or in flight. Never overwrite or free a
descriptor slot still referenced by recorded or in-flight work. Test GPU
completion, retained states and payloads, dropped work, safe recycling, capacity
failure, and any growth policy.

R6 — Explicit scheduling. FX2 records work and never implicitly submits, presents,
or waits. Applications submit SSC-prepared producers before their consumers. A
pass returns only its own work and does not duplicate shared producers. Dropped
initialization must support retry or explicitly reject uninitialized consumption.
Immediate CPU values are copied and GPU resources retained. Blocking transfers
(Buffer::setContent, Buffer::readContent, Texture::readback) are for tests,
debugging, and one-shot initialization only.

R7 — Verification. Wrapper Debug build, formatting/lint/CIT, and focused SSC tests
pass under Vulkan validation with no unexpected errors, warnings, performance
warnings, or lifetime leaks. Scope expected negative-test diagnostics explicitly.
Record exact commands and results, plus untested platform/backend gaps.

## Design

### Namespace and incremental scope

All new code lives in GN::fx2::bindless, in new files. Existing classes and shaders
are not refactored into this namespace. Shared build and include wiring gains
additive entries only. Implement one unit at a time and verify it before advancing;
do not batch the two stores into one broad change. The stash is reference only —
reuse small reviewed pieces solely when they satisfy this contract.

### Private Vulkan GPU layout

The layout is private to the bindless implementation. Other backends may lower
these contracts differently. Only set 1 is SSC's to define:

  Set 0             : gpu2 descriptor heap — organization owned by gpu2
  Set 1, binding 0  : CPU-to-GPU streaming SSBO            (SSC streaming pool)
  Set 1, binding 1  : generic versioned SSC uniform buffer (SSC uniform store)
  Set 2+            : optional explicit pass resources

Set 0's descriptor and material contracts belong to gpu2 and are documented
in src/core/gpu2/README.md. Callers provide the heap directly to Raster/CnC;
SSC has no heap dependency.

Set 1 is provided through Raster/CnC CreateParameters::passResources, indexed by
absolute set/binding/array indices. passResources[heapSetIndex] must be empty.
SSC supplies streaming at binding 0 (BufferView::STORAGE) and uniforms at binding 1
(BufferView::UNIFORM). Empty slots are skipped by the pipeline-layout builder and
the descriptor writer, so the two stores can be delivered independently.

Environment resources have no dedicated bindings. Later FX2 sky schemas store
texture/sampler indices in opaque heap-owned chunks; combined scene uniform
schemas reference the selected chunk. SSC does not interpret either schema.

### Decomposition

The SSC facade is thin. It owns two independent storage subsystems, each
with its own private header and implementation file. They can be implemented
independently against fixed interfaces without touching the same file. The
facade receives a GPU context directly; it does not own a descriptor heap.

    bindless-ssc-uniform-store.h/.cpp    R1  versioned uniform ranges
    bindless-ssc-stream-pool.h/.cpp      R3  mapped one-time-use ranges
    bindless-shared-shader-constants.cpp facade: composes two stores on the supplied GPU context

The private subsystem headers are the contract between the facade and each unit. An
implementer fills in the .cpp against the header it is given, and reports any
interface that is genuinely wrong rather than changing it unilaterally.

Kernels later define their typed inputs and private shader schemas, provide values
to SSC, and record consumers of SSC-managed data. They do not own separate arenas
or independently manage uploads of shared records. Each kernel controls its
complete push-constant layout: ordinary transforms, flags, and optional material
references use push constants, with no universal packet or mandatory
material-address field. Vertex and index buffers remain ordinary geometry bindings.

### Uniform store internals

One long-lived pool buffer carved into aligned ranges. An update call takes opaque
bytes plus a size, allocates a fresh range, records the upload on the caller-supplied
CnC, and returns a retained state exposing that range as a GpuResourceView for set 1,
binding 1. Range offsets must satisfy minUniformBufferOffsetAlignment and each range
size must stay within maxUniformBufferRange. Ranges are recycled by lease, not by
upload completion. The growth policy must be explicit and tested: either enlarge the
pool preserving outstanding ranges, or fail at a documented capacity.

### Streaming pool internals

One or a few long-lived mappable buffers, kept mapped for their lifetime. gpu2
mappable buffers are HOST_VISIBLE|HOST_COHERENT (vk-buffer.cpp:52) and rapid-vulkan
marks every host-visible allocation VMA_ALLOCATION_CREATE_MAPPED_BIT
(rapid-vulkan.cpp:261), so no cache flush is required and repeated map/unmap is
avoided. Note that gpu2 Buffer::map() is exclusive: mapping an already-mapped buffer
is an error (vk-buffer.cpp:77), so the pool must map each backing buffer once and
hold the mapping, following the CncUploadStorage pattern at vk-cnc-common.h:129.
Allocation is a bump or free-list advance over the mapped range; release recycles
the range. Release is driven by the consuming payload, never by mapping state.

### Uploads, cancellation, and hazards

Applications schedule producers once before their consumers. No implicit submit or
wait. Bindless indices do not describe resource hazards: track actual sampled,
storage, attachment, geometry, transfer, and compute-write uses explicitly, and
reject unsupported attachment feedback before recording.
