TITLE: Python DDS/EXR Texture Viewer (tex-viewer)

GOAL
  A standalone Python/Qt5 image viewer for DDS and EXR files with:
    - Full mipmap chain: navigate every mip level, see correct dimensions per mip
    - All texture types: 2D, cubemap (6 named faces), 2D array, 3D/volume (depth slices)
    - Zoom (wheel), pan (drag), fit-to-window (F), 1:1 (1)
    - Exact raw float R/G/B/A pixel values under mouse cursor
    - HDR display with configurable tonemapping (5 modes, exposure, gamma)
    - BCn compressed DDS (BC1/2/3/4/5/6H/7): decode via texture2ddecoder
    - UX: drag-drop, recent files, window title, keyboard shortcuts
  "Done" = every item in this list is exercised by a test or demo pass.

KNOWN BUGS (fix before adding new features)
============================================

Bug B1: decode_bc6 return type assumed wrong  ← MOST IMPORTANT
  PROBLEM: dds.py._decode_bcn() calls decode_bc6() and then reads result as
           float16 RGB. But texture2ddecoder.decode_bc6() actually returns
           BGRA uint8 bytes (64 bytes for a 4×4 block = 4 bytes/pixel),
           not float16.  BC6H HDR textures will display garbage/crash.
  FIX:
    - Change _decode_bcn for BC6H_UF16/BC6H_SF16:
        raw_out = t2d.decode_bc6(raw, w, h)
        out = np.frombuffer(raw_out, dtype=np.uint8).reshape(h, w, 4).copy()
        out = out[:, :, [2, 1, 0, 3]].astype(np.float32) / 255.0  # BGRA→RGBA
      Note: this loses HDR range (all values clamped to [0,1]).
      Mark output channels as "HDR data unavailable; decoded to LDR uint8" in
      a comment, and document the limitation in a TODO.
  VERIFY:
    python3 -c "
    import sys; sys.path.insert(0,'env/bin')
    from tex_viewer.dds import _decode_bcn, Fmt
    import numpy as np
    dummy = bytes(16)   # one empty 4×4 BC6H block
    out = _decode_bcn(dummy, 4, 4, Fmt.BC6H_UF16)
    assert out.shape == (4, 4, 4), out.shape
    assert out.dtype == np.float32, out.dtype
    print('B1 fix verified')
    "
  COMMIT: "tex-viewer B1: fix BC6H decode (uint8 path, not float16)"

Bug B2: texture2ddecoder has no decode_bc2
  PROBLEM: dds.py calls t2d.decode_bc2() but that function does not exist
           in texture2ddecoder. Any BC2 DDS will crash with AttributeError.
  FIX:
    - texture2ddecoder only has decode_bc1/3/4/5/6/7.  BC2 (DXT3) is rarely
      used in practice.  Options:
        (a) Raise a clear error: "BC2/DXT3 not supported by texture2ddecoder".
        (b) Fallback: decode as BC3 (alpha channel will differ but won't crash).
      Choose (a): raise ValueError with a helpful message.
  VERIFY:
    python3 -c "
    import sys; sys.path.insert(0,'env/bin')
    from tex_viewer.dds import _decode_bcn, Fmt
    try:
        _decode_bcn(bytes(16), 4, 4, Fmt.BC2_UNORM)
        print('ERROR: should have raised')
    except (ValueError, RuntimeError) as e:
        print('B2 fix verified:', e)
    "
  COMMIT: "tex-viewer B2: raise clear error for BC2 (decode_bc2 absent)"

Bug B3: 3D depth-slice range not updated when mip changes
  PROBLEM: main_window._on_face_changed() updates depth spin range for 3D textures
           but it is connected to spin_face, NOT spin_mip.  When the user advances
           the mip level of a 3D texture, the depth-slice spin keeps the wrong max
           (base depth instead of base_depth >> mip).
  FIX:
    - Move the depth-range update out of _on_face_changed into a new helper
      _update_depth_range() called from both _on_nav_changed and _on_face_changed.
    - _update_depth_range():
        if self._dds and self._dds.tex_type == TexType.TEX3D:
            mip = self._spin_mip.value()
            new_max = max(0, max(1, self._dds.depth >> mip) - 1)
            old_val = self._spin_depth.value()
            self._spin_depth.setRange(0, new_max)
            self._spin_depth.setValue(min(old_val, new_max))
  VERIFY:
    Manual: open a 3D DDS with ≥2 mip levels; advance mip → depth max halves.
    OR: unit test with a synthetic DDS (see Phase 3.1).
  COMMIT: "tex-viewer B3: fix 3D depth-range update when mip changes"

Bug B4: White-point row visible at startup when it should be hidden
  PROBLEM: _lbl_white and _spin_white are added to tm_lay and are VISIBLE by
           default. They should only appear when mode == Reinhard Extended.
           At startup (mode = Linear), they are shown but should be hidden.
  FIX:
    After building the tonemapping panel, add:
        self._lbl_white.setVisible(False)
        self._spin_white.setVisible(False)
  VERIFY:
    python3 -c "
    import sys, os; sys.path.insert(0,'env/bin')
    os.environ.setdefault('DISPLAY',':0')
    from PyQt5.QtWidgets import QApplication
    from PyQt5.QtCore import QTimer
    from tex_viewer.main_window import MainWindow
    app = QApplication([])
    w = MainWindow()
    w.show()
    # white_point row should be hidden at startup (mode=Linear)
    assert not w._spin_white.isVisible(), 'white_point visible at startup!'
    print('B4 fix verified')
    app.quit()
    "
  COMMIT: "tex-viewer B4: hide white-point row at startup"

Bug B5: Zoom level label never updates

Phase 5: Display Improvements
====================================================================

Task 5.1: sRGB linearisation toggle
  DDS files flagged as sRGB (R8G8B8A8_UNORM_SRGB, BC1_UNORM_SRGB, etc.) currently
  display without linearization.  For correct tonemapping they should be linearised
  before tonemapping.
  Add a checkbox "sRGB → Linear" in the Tonemapping group.
  When checked and is_srgb is True, apply sRGB→linear before tonemapping:
      x_lin = np.where(x <= 0.04045, x/12.92, ((x+0.055)/1.055)**2.4)
  VERIFY:
    Make or find an sRGB DDS; toggle the checkbox → visible brightness change.
  COMMIT: "tex-viewer 5.1: sRGB linearisation toggle"

Task 5.2: Alpha premultiplied / straight alpha toggle
  Some DDS files store premultiplied alpha.  Add a "Premultiplied α" checkbox.
  When checked, un-premultiply before display:
      rgb = rgb / (alpha + 1e-6)    (clamp alpha to [0,1] first)
  VERIFY:
    Manual inspection with a known premultiplied-alpha texture.
  COMMIT: "tex-viewer 5.2: premultiplied alpha toggle"

Task 5.3: Display normalised-normal-map mode
  BC5 / R16G16 textures are often normal maps (RG encoded, B reconstructed).
  Add a "Normal Map" display mode that reconstructs B = sqrt(1-R²-G²) and
  remaps [-1,1]→[0,1] for display.
  Enabled automatically when format is BC5 / R16G16 and user has not overridden.
  VERIFY:
    Open a BC5 normal map → blue channel appears, surface normals visible.
  COMMIT: "tex-viewer 5.3: normal-map reconstruction mode for RG/BC5 textures"

Task 5.4: Zoom-to-fit respects HiDPI (devicePixelRatio)
  On HiDPI displays the canvas widget size in logical pixels differs from the
  physical pixel count.  QPixmap.devicePixelRatio() should be set correctly.
  VERIFY:
    On a HiDPI display the image does not appear 2× too large.
    (Low-priority; skip if no HiDPI system available.)
  COMMIT: "tex-viewer 5.4: HiDPI devicePixelRatio fix"

Phase 6: Performance
====================================================================

Task 6.1: Async loading for large files
  Large EXR files (>50 MB) freeze the UI during load.
  Move file I/O + decode into a QThread worker; show "Loading…" in status bar
  and disable nav controls until done.  On completion update UI in main thread.
  VERIFY:
    Open the 10K EXR; status shows "Loading..." and UI stays responsive.
  COMMIT: "tex-viewer 6.1: async file loading via QThread"

Task 6.2: Cache decoded subresources
  Navigating between faces or mip levels of the same DDS re-decodes from bytes
  each time.  Add an LRU cache (max 32 MB) keyed by (path, array_idx, mip,
  depth_slice) → float32 RGBA array.  Invalidate cache on new file open.
  VERIFY:
    Navigate cubemap faces → CPU usage drops after first visit.
  COMMIT: "tex-viewer 6.2: LRU subresource decode cache"
