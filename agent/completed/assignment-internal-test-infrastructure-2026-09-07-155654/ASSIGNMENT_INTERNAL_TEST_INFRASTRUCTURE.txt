# Assignment: Internal Unit Test Infrastructure

---

## Goal

The current unit-test binary (`GNtest-unit-tests`) is built as a standalone executable
that links `GNcore.dll/.so` but only has access to the public headers under
`src/inc/garnet/`.  This works as a contract/smoke tester, but it cannot:

  - Include private implementation headers (e.g. `src/core/rdg/submission.h`)
  - Access `private:` members of internal types
  - Unit-test a sub-system (e.g. RDG) without going through the public API

"Done" means:

  1. `src/core/CMakeLists.txt` is refactored to produce a `GNcore-objects` OBJECT
     library from which both `GNcore.dll/.so` and `GNtest-internal` are built.
     Production code is compiled exactly ONCE.
  2. A second test target, `GNtest-internal`, exists and passes CI.
  3. `GNtest-internal` can `#include` any private header under `src/core/` directly
     AND can call any internal function without linker errors.
  4. Test source files live side-by-side with the code they test, under
     `src/core/<module>/test/`.
  5. Catch2 is wired in as the framework for the new target (CxxTest remains
     untouched for the legacy `GNtest-unit-tests`).
  6. At least two meaningful internal test cases exist that would be impossible
     from the public-only tier.
  7. `env/bin/cit.py` runs both `GNtest-unit-tests` and `GNtest-internal`.
  8. A conventions note in `src/test/README.md` explains the two-tier model.

---

## Background: Why the current setup falls short

### What works
`GNtest-unit-tests` proves the public API contract.  It is the right tool for
regression-testing what an external consumer of `GNcore` can observe.

### The two-layer problem

Getting a test to call an internal function requires solving TWO independent
problems: compile-time visibility and link-time visibility.

**Layer 1 — compile-time (include path)**
The test binary has no `target_include_directories` pointing to `src/core/`, so
the compiler cannot find private headers.  Consequence: `#include "rdg/submission.h"`
fails at compile.

**Layer 2 — link-time (symbol visibility)**  ← the harder, less obvious problem
`GNcore` is built as a shared library.  On Linux, it is compiled with
`-fvisibility=hidden` (see `src/core/CMakeLists.txt` line ~252).  On Windows,
only symbols marked `__declspec(dllexport)` (`GN_API`) are exported.  Internal
implementation symbols are stripped from the export table.

Therefore: even after fixing the include path, a test file that calls an internal
function will fail at **link** with "unresolved external symbol" because the
symbol is not exported from `GNcore.dll/.so`.

**The root cause**
`GNtest-unit-tests` is linked against `GNcore` (the shared library).  To call
unexported symbols the test binary must not go through the DLL at all — it must
link the object files directly.

## Design: Two-tier test infrastructure

### Tier 1 — External / contract tests  (keep as-is)

  Target:    GNtest-unit-tests
  Framework: CxxTest  (unchanged)
  Sources:   src/test/ut/
  Links:     GNcore.dll/.so  (public API only)
  Purpose:   Verify the public API; black-box tests.

  No changes to this tier in this assignment.

### Tier 2 — Internal / white-box tests  (new)

  Target:    GNtest-internal
  Framework: Catch2
  Sources:   src/core/**/test/*.cpp  (side-by-side with the code under test)
  Links:     GNcore-objects directly (bypasses DLL export table)
  Purpose:   Test implementation details, private helpers, internal state.

#### Key: compile production code ONCE via a CMake OBJECT library

  The production sources are extracted into an intermediate OBJECT library,
  `GNcore-objects`, that is compiled exactly once.  Both `GNcore` (the shipping
  shared library) and `GNtest-internal` (the test executable) consume those same
  object files:

    src/core/**/*.cpp  compiled ONCE
            │
            ▼
      GNcore-objects  (.o / .obj files)
       ┌────┴────┐
       ▼         ▼
    GNcore      GNtest-internal
    (.dll/.so)  (executable)
    exports     links object files
    via GN_API  directly — all
    only        symbols visible

  CMake OBJECT library sketch (to replace the current `add_library(GNcore ...)` block
  in `src/core/CMakeLists.txt`):

    # 1. Compile sources once
    add_library(GNcore-objects OBJECT ${sources} ${garnet_headers})
    set_target_properties(GNcore-objects PROPERTIES POSITION_INDEPENDENT_CODE ON)
    target_compile_definitions(GNcore-objects PRIVATE GN_CORE_INTERNAL)
    target_include_directories(GNcore-objects
        PUBLIC  ${BUILD_HEADER_INC} ../inc ../3rdparty/glm
                ../3rdparty/rapid-image/inc ../3rdparty/fmt/include
        PRIVATE ../3rdparty/stb ../3rdparty/backward-cpp)
    # ... (apply all remaining target_compile_definitions / options / link libs
    #      that used to be on GNcore, now applied to GNcore-objects instead)

    # 2. Production shared library: wraps the objects, adds DLL export table
    if(GN_BUILD_IS_STATIC)
        add_library(GNcore STATIC)
    else()
        add_library(GNcore SHARED)
    endif()
    target_link_libraries(GNcore PUBLIC GNcore-objects GNextern)

  Then `GNtest-internal` links `GNcore-objects` directly:

    file(GLOB_RECURSE test_sources
        ${GARNET_ROOT}/src/core/**/test/*.cpp)
    add_executable(GNtest-internal ${test_sources})
    target_include_directories(GNtest-internal PRIVATE
        ${GARNET_ROOT}/src/core)          # private headers visible to tests
    target_link_libraries(GNtest-internal PRIVATE
        GNcore-objects                    # all symbols, no DLL filter
        GNextern
        Catch2::Catch2WithMain)

  Because `GNtest-internal` links the raw object files (not the shared library),
  the DLL export table is bypassed entirely.  Every internal function is visible
  to the linker.

#### Test source file placement — side-by-side

  Test files live next to the code they test:

    src/core/
      rdg/
        submission.cpp
        submission.h              ← private header
        test/
          submission-test.cpp    ← test file; can include ../submission.h
      base/
        array.h
        test/
          array-test.cpp

  The `file(GLOB_RECURSE test_sources src/core/**/test/*.cpp)` in
  `GNtest-internal`'s CMakeLists automatically picks up every test file.
  Adding a new test file to any `test/` subfolder is all that is needed.

#### Access model for internal code

  | What you want to test | How | Production code change? |
  |---|---|---|
  | Internal types in private headers | `#include "rdg/submission.h"` via PRIVATE src/core include path | None |
  | Any function in a private header | Direct call (linker sees obj files) | None |
  | `private:` members of a public type | Manual `friend` declaration in production header | One line |
  | `static` / anon-ns fn in a `.cpp` | Promote to private header, or accept indirect coverage | Minor refactor |

  A manual `friend` declaration is a last resort for `private:` members of types
  declared in *public* headers.  Internal impl types (Layer 1) are typically plain
  `struct`s with all-public fields — friendship is not needed.

#### Why Catch2 for Tier 2

  | Feature | CxxTest | Catch2 |
  |---|---|---|
  | No code-generation pre-build step | No (cxxtestgen.py) | Yes |
  | Automatic expression decomposition in failure messages | No | Yes |
  | SECTION blocks (sub-cases sharing setup) | No | Yes |
  | GENERATE (parameterized tests, no fixture boilerplate) | No | Yes |
  | Simple CMake integration (single target, no code-gen) | No | Yes |
  | IDE test discovery (VS Code, CLion) | No | Yes |

  Catch2 requires no Python pre-build step (unlike CxxTest) and no separate mock
  library for the test cases in scope.  If mocking or death-tests are needed later,
  Trompeloeil pairs naturally with Catch2.

  CxxTest is kept for Tier 1 to avoid unnecessary churn; it is already passing.

### Optional Tier 3 — Embedded micro-tests  (future / optional, not in this assignment)

  Framework: doctest (header-only, designed for co-location with source)
  Pattern:   Place TEST_CASE blocks at the bottom of production .cpp files.
             Define DOCTEST_CONFIG_DISABLE in production builds to strip them out.
  Use when:  A `static`/anonymous-namespace helper in a .cpp file is complex enough
             to need its own test but too small to deserve its own private header.

  - Keep GNtest-unit-tests green at every step (never break it).
  - Commit after each task is done and verified (assignment-commit-per-step rule).
  - Push after every commit (git push).
  - New test files go in src/core/<module>/test/<name>-test.cpp.
  - File names follow filename-naming-convention (lowercase, hyphen-separated).
  - Prefer private-include + object-link access for internal types (plain structs
    in private headers have all-public fields — no friendship needed).
  - If a `private:` member of a *public* type is unavoidable to test, use a named
    `friend struct` in the production header (one line); do not change access to
    protected/public just for tests.
  - GNtest-internal MUST NOT link GNcore (.dll/.so).  It links GNcore-objects only.
    Linking both would cause duplicate symbol errors.

### Task 2a — Refactor src/core/CMakeLists.txt: extract GNcore-objects

  What:
    Replace the current `add_library(GNcore ...)` block with:
      1. `GNcore-objects` (OBJECT library) — compiled once, holds all production .o files.
      2. `GNcore` (SHARED or STATIC as before) — now just wraps GNcore-objects.

    All `target_include_directories`, `target_compile_definitions`,
    `target_compile_options`, `target_compile_features`, and `add_core_libs` calls
    that currently apply to `GNcore` must be moved to apply to `GNcore-objects`
    (or kept on `GNcore` with PUBLIC propagation — see note below).

  Key implementation notes:
    - Set POSITION_INDEPENDENT_CODE ON on GNcore-objects so the same .o files
      can be used in both GNcore.so (needs PIC) and GNtest-internal (no strict need,
      but harmless).
    - The add_core_libs() helper function currently calls target_link_libraries on
      GNcore.  Refactor it (or add a parallel one) to apply to GNcore-objects.
    - GNcore (SHARED/STATIC) simply does:
        target_link_libraries(GNcore PUBLIC GNcore-objects GNextern)
      It no longer lists sources — it gets them from GNcore-objects.
    - On Linux the -fvisibility=hidden flag was applied to GNcore PRIVATE.
      Move it to GNcore-objects PRIVATE.  It still correctly hides symbols in
      GNcore.so; for GNtest-internal the flag has no harmful effect (the test
      executable links objects statically, so visibility attributes are irrelevant).

  Sketch of the refactored block (replaces lines ~96-257 in src/core/CMakeLists.txt):

    # --- compile once ---
    add_library(GNcore-objects OBJECT ${sources} ${garnet_headers})
    set_target_properties(GNcore-objects PROPERTIES POSITION_INDEPENDENT_CODE ON)

    target_compile_features(GNcore-objects PUBLIC cxx_std_20)
    target_compile_definitions(GNcore-objects PRIVATE GN_CORE_INTERNAL)
    target_include_directories(GNcore-objects PUBLIC
        ${BUILD_HEADER_INC} ../inc
        ../3rdparty/glm ../3rdparty/rapid-image/inc ../3rdparty/fmt/include)
    target_include_directories(GNcore-objects PRIVATE
        ../3rdparty/stb ../3rdparty/backward-cpp)

    # redefine add_core_libs to target GNcore-objects
    function(add_core_libs)
        target_link_libraries(GNcore-objects PUBLIC ${ARGN})
    endfunction()

    # ... all the existing conditional blocks (GLFW, Vulkan, FBX, Threads,
    #     assimp, freetype, iconv, MSVC flags, -fvisibility=hidden) stay here,
    #     but now call add_core_libs / target_compile_definitions on GNcore-objects ...

    # --- production library: just wraps the objects ---
    if(GN_BUILD_IS_STATIC)
        add_library(GNcore STATIC)
    else()
        add_library(GNcore SHARED)
    endif()
    target_link_libraries(GNcore PUBLIC GNcore-objects GNextern)
    if(TARGET GNcore-rdg-shaders)
        add_dependencies(GNcore GNcore-rdg-shaders)
    endif()

  Verify:
    ./build.py d — GNcore.so/.dll builds.  Run GNtest-unit-tests to confirm no

### Task 3 — Write first real internal test: vk-format-utils conversions

  What:
    Test pixelFormatToVkFormat() and vkFormatToPixelFormat() declared in the
    private header src/core/rdg/vk-format-utils.h.  These functions are:
      - Undiscoverable from Tier 1 (header not on public include path).
      - Unlinkable from Tier 1 (symbols not exported from GNcore.dll/.so).
    They are pure table-lookup routines with no GPU context or Vulkan device
    required — ideal for fast, hermetic unit tests.

  Test cases to cover:

    1. vkFormatToPixelFormat: known formats map to the expected PixelFormat.
         eR8G8B8A8Unorm → PF::RGBA_8_8_8_8_UNORM()
         eR32Sfloat     → PF::R_32_FLOAT()
         eD24UnormS8Uint → PF::RG_24_UNORM_8_UINT()
         eUndefined     → PF::UNKNOWN()
         out-of-range   → PF::UNKNOWN()

    2. pixelFormatToVkFormat: known PixelFormats map to the expected vk::Format.
         PF::RGBA_8_8_8_8_UNORM() → eR8G8B8A8Unorm
         PF::R_32_FLOAT()         → eR32Sfloat
         PF::UNKNOWN()            → eUndefined

    3. Round-trip (GENERATE parameterized): for a representative set of vk::Format
       values that have a known (non-UNK) mapping, verify:
         pixelFormatToVkFormat(vkFormatToPixelFormat(fmt)) == fmt
       Use Catch2's GENERATE to run one TEST_CASE body over each input — no
       fixture class or separate TEST_CASE per format needed.

  Create src/core/rdg/test/vk-format-utils-test.cpp:

    #include <catch2/catch_test_macros.hpp>
    // Both includes below fail in GNtest-unit-tests and fail to link against
    // GNcore.dll — they only work in GNtest-internal:
    #include "rdg/vk-format-utils.h"
    #include <garnet/GNrdg.h>

    using namespace GN::rdg;
    using PF = GN::gfx::img::PixelFormat;

    TEST_CASE("vkFormatToPixelFormat: known formats", "[rdg][format]") {
        CHECK(vkFormatToPixelFormat(vk::Format::eR8G8B8A8Unorm) == PF::RGBA_8_8_8_8_UNORM());
        CHECK(vkFormatToPixelFormat(vk::Format::eR32Sfloat)     == PF::R_32_FLOAT());
        CHECK(vkFormatToPixelFormat(vk::Format::eD24UnormS8Uint) == PF::RG_24_UNORM_8_UINT());
        CHECK(vkFormatToPixelFormat(vk::Format::eUndefined)     == PF::UNKNOWN());
        CHECK(vkFormatToPixelFormat(static_cast<vk::Format>(9999)) == PF::UNKNOWN());
    }

    TEST_CASE("pixelFormatToVkFormat: known formats", "[rdg][format]") {
        CHECK(pixelFormatToVkFormat(PF::RGBA_8_8_8_8_UNORM()) == vk::Format::eR8G8B8A8Unorm);
        CHECK(pixelFormatToVkFormat(PF::R_32_FLOAT())         == vk::Format::eR32Sfloat);
        CHECK(pixelFormatToVkFormat(PF::UNKNOWN())            == vk::Format::eUndefined);
    }

    TEST_CASE("round-trip: vkFormat → pixelFormat → vkFormat", "[rdg][format]") {
        // GENERATE runs this body once per value — Catch2 parameterized test.
        auto fmt = GENERATE(
            vk::Format::eR8G8B8A8Unorm,
            vk::Format::eR8G8B8A8Snorm,
            vk::Format::eR32Sfloat,
            vk::Format::eR16Sfloat,
            vk::Format::eR8Unorm,
            vk::Format::eR8Uint,
            vk::Format::eD24UnormS8Uint,
            vk::Format::eBc1RgbUnormBlock,
            vk::Format::eBc7UnormBlock);
        PF pf = vkFormatToPixelFormat(fmt);
        REQUIRE(pf != PF::UNKNOWN());                         // must have a mapping
        CHECK(pixelFormatToVkFormat(pf) == fmt);              // round-trip must hold
    }

  No CMake change needed — GLOB_RECURSE picks up the new file automatically
  (a cmake reconfigure is required to refresh the glob).

  Verify:
    ./build.py d
    ./build/debug/GNtest-internal — all 3 test cases pass (round-trip runs 9 times).
    Confirm: adding #include "rdg/vk-format-utils.h" to a file in src/test/ut/
    causes a compile error (proving tier separation is enforced).
