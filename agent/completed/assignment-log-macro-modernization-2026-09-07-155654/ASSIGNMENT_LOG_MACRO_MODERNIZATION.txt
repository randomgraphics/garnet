# Assignment: Log Macro Modernization — variadic call syntax, dual format/stream support, statement-safe expansion

---

## Goals

Replace the trailing-call log macro syntax `GN_ERROR(logger)("format", args...)` with a
single variadic form `GN_ERROR(logger, "format", args...)`. The trailing-call shape is
unusual, it forces the macro to expand to a dangling `if/else`, and it makes the macro an
expression fragment rather than a statement.

Three concrete defects are being fixed:

1. `if (cond) GN_ERROR(sLogger)("x");` emits `-Wdangling-else` ("suggest explicit braces to
   avoid ambiguous 'else'") on GCC, because the macro expands to
   `if (logger->isOff(level)) {} else <helper>.format`, nesting an if/else inside an if.
2. The logger expression is evaluated twice per call — once for `isOff()`, once for the
   `LogHelper` constructor. Sites like `GN_ERROR(getLogger("GN.base.HandleManager"))(...)`
   pay two name lookups.
3. `isOff()`-then-`else` gives the compiler no branch hint at all, so the overwhelmingly
   common log-is-off path is not favored.

Two capabilities are being added:

4. One macro must accept BOTH comma-separated format arguments and the streaming operator:
   `GN_INFO(logger, "a = {}", a)` and `GN_INFO(logger << "a = " << a)`.
5. printf syntax becomes officially supported alongside fmt brace syntax, in the same
   macro. The log macros are used to redirect third-party library logging (rapid-image
   today, rapid-vulkan style generally), and those libraries emit printf format strings.
   The existing "Printf syntax is deprecated" assert is removed.

Finally, three obsolete configuration knobs in `config.h` are deleted. None of them is set
by any build configuration, so each is an indirection with exactly one meaning:

6. `GN_ENABLE_LOG` — defined to 1, read in exactly one place. Dead configuration surface;
   removed outright along with the disabled branch it guarded.
7. `GN_ENABLE_ASSERT` — defaults to `GN_BUILD_DEBUG_ENABLED`, so unlike `GN_ENABLE_LOG` it
   does real work: asserts compile out in release builds. Removed as a *knob* only; its two
   use sites substitute `GN_BUILD_DEBUG_ENABLED` directly, so behavior is unchanged.
8. `GN_ENABLE_GPU_DEBUG_MARK` — defaults to
   `(GN_BUILD_DEBUG_ENABLED || GN_BUILD_PROFILING_ENABLED)` and has a single use site.
   Removed as a knob; `gpu.h` checks the two build flags directly.

`GN_ENABLE_GUARD` and `GN_ENABLE_SLOW_GUARD` are deliberately left in place: they have a
real interdependency (`GN_ENABLE_SLOW_GUARD` is ignored when `GN_ENABLE_GUARD` is off) and
two use sites in `exception.h`.

## Design

### Macro signatures

    GN_FATAL(logger, ...)      GN_ERROR(logger, ...)     GN_WARN(logger, ...)
    GN_INFO(logger, ...)       GN_VERBOSE(logger, ...)   GN_BABBLE(logger, ...)
    GN_TRACE(logger, ...)      GN_VTRACE(logger, ...)    GN_VVTRACE(logger, ...)
    GN_LOG(logger, level, ...)
    GN_LOG_EX(logger, level, func, file, line, ...)
    GN_PRINTF_EX(logger, level, func, file, line, ...)

Every signature keeps its original parameter order. The trailing format argument list is optional,
carried by `, ##__VA_ARGS__` — the same comma-elision extension already used by GN_ASSERT_FAILURE in
debug.h, and the reason __VA_OPT__ is avoided (it needs /Zc:preprocessor, which this project does not
set).

### One macro, both syntaxes

The expansion ends in an expression of type `LogHelper &`, so a streaming expression can be appended
to any form and the two syntaxes compose in a single statement:

    GN_ERROR(logger);                                  // nothing logged
    GN_ERROR(logger, "a = {}", a);                     // comma parameter list
    GN_ERROR(logger) << "a = " << a;                   // streaming
    GN_ERROR(logger, "a = {}", a) << ", b = " << b;    // both -> "a = 1, b = 2"

LogHelper owns both: operator<< appends to a lazily created stream, emit() either goes straight to
the logger when nothing was streamed or appends to the streamed prefix, and the destructor reports
whatever is left. emit() and emitPrintf() return *this, which is what makes the chaining work; the
no-argument emit() overload is what makes the streaming-only form work.

### Off path is a single level test

    #define GN_LOG_EX(logger, level, func, file, line, ...) \
        switch (0)                                          \
        case 0:                                             \
        default:                                            \
            if ((logger)->isOff(level)) GN_LIKELY            \
                ;                                           \
            else                                            \
                ::GN::Logger::LogHelper(logger, level, func, file, line).emit(__VA_ARGS__)

The whole payload sits in the else branch, so when the level is off nothing is constructed and no
format or streamed argument is evaluated. Verified in generated code at -O2 for the format-only,
streaming-only and mixed forms: the off path is a logger load, `cmpb`, `je`, `movl`, `testl`, `jne`
to the cold block, then the epilogue. Zero initialization stores.

Two earlier designs were measured and rejected. Fusing the logger into the message expression
(`GN_ERROR(logger << "a" << a)`) makes the logger inseparable from the first macro argument, so
nothing can precede the level test; that shape cost 6 dead initialization stores and a 120-byte frame
on every off path, and the stores could not be eliminated because doLog(const LogLocation &, ...)
takes the helper's address into a virtual call. Wrapping in do/while(false) has the same problem.

`switch (0) case 0: default:` is what keeps this a complete statement. Without it,
`if (cond) GN_ERROR(...);` nests an if/else inside an if, which trips -Wdangling-else and makes a
following `else` bind to the wrong if. This is the same guard glog uses for the same reason.

Because the level test is a plain `if` whose taken branch is empty, GN_LIKELY marks the off path
directly rather than relying on the compiler to guess.

### printf / fmt syntax autodetection

emit() keeps the fmt::format_string / fmt::wformat_string parameter type, so genuine fmt strings
retain compile-time format checking. At runtime it routes to fmt::sprintf when the string carries a
printf conversion specifier and no brace replacement field, and to fmt::format otherwise.

This works because fmt (bundled: 12.0.0) tolerates unused arguments and treats %d as literal text, so
a printf string passes the compile-time check as a zero-field format string. Verified against the
bundled fmt.

Resolution rules, locked by unit tests:
  - "a = %d"      -> printf
  - "a = {}"      -> fmt
  - "{} %d"       -> fmt (a brace field wins; the string is ambiguous)
  - "{{literal}}" -> fmt (brace escape)
  - "100%% done"  -> printf. A lone %% escape counts as printf syntax, so it is unescaped to
                    "100% done", matching GN_PRINTF_EX.
  - "{}%% done"   -> fmt (the brace field wins), so the percent stays doubled
  - "50 percent %" -> fmt. A trailing bare percent is not a conversion specifier.

Consequence worth knowing: because the branch is a runtime test, both the fmt and the printf paths are
instantiated for every call. Every log argument type must therefore be formattable in fmt's printf
context as well as its normal context. This is what dictates the shape of the GN::Str formatter below.

### Passing string types directly

GN::StrA, GN::StrW, std::string and std::wstring can all be passed to a format string with no
.data() or .c_str(). std::string and std::wstring already worked. GN::Str did not, for two reasons,
both fixed in string.h:

  - fmt::formatter<GN::StrW> was specialized on the default (narrow) character type while formatting
    with a wide format string, so GN::StrW had no formatter inside a wide format string at all. The
    specialization is now on <GN::Str<CHAR, ALLOC>, CHAR>, covering both character types and any
    allocator.
  - GN::Str is iterable, so fmt's range formatter matched it and would print "['a', 'b']". Worse, that
    range specialization and the new one are both partial specializations of
    formatter<Str<CHAR, ALLOC>, CHAR, void> with neither more specialized, which is an ambiguity error.
    range_format_kind<GN::Str<CHAR, ALLOC>, CHAR> is now specialized to range_format::disabled, which
    resolves both problems. The old code avoided the ambiguity only by being a full specialization.

The formatter deliberately ignores format specifications (its parse() returns ctx.begin()) and writes
characters straight to the output iterator, because the spec-handling machinery behind
basic_string_view does not compile in fmt's printf context. Preserving "{:>10}" padding for Str would
require dropping printf autodetection.

### Known limitation

A streamed operand must be appended with `<<` rather than fused into the logger argument. The fused
spelling `GN_ERROR(logger << "a" << a)` is not supported and cannot be: the logger has to be a
separate macro parameter for the level test to precede everything else. `GN_ERROR(logger) << "a" << a`
is the supported spelling and is strictly better, since it is gated before its operands are
evaluated.

### Configuration knob removal

`GN_ENABLE_LOG` is deleted from `config.h` and `log.h`. `GN_BUILD_DEBUG_ENABLED` continues to gate the
GN_TRACE / GN_VTRACE / GN_VVTRACE family in non-debug builds; that disabled path expands to
`if (false) <sink>` so arguments still type-check (catching bit-rot, and keeping log-only
locals "used"). `Logger::sFakeLog` changes from C-varargs to a variadic template, because
passing non-trivial types such as `std::string` through `...` is ill-formed.

`GN_ENABLE_ASSERT` is deleted from `config.h`; `debug.h` and `core/gpu/util/cmdbuf.cpp`
test `GN_BUILD_DEBUG_ENABLED` directly instead. `GN_ENABLE_GPU_DEBUG_MARK` is deleted from
`config.h`; `gfx/gpu.h` tests `(GN_BUILD_DEBUG_ENABLED || GN_BUILD_PROFILING_ENABLED)`
directly. Both substitutions are behavior-preserving by construction.

### Test framework migration

Log tests move from the retiring CxxTest suite (`src/test/ut/base/log.cpp`) to the Catch2
internal-test framework: new `src/core/base/test/log-test.cpp` registered via a new
`src/core/base/test/internal-test.cmake`, picked up automatically by the
`src/core/*/test/internal-test.cmake` glob in `src/test/internal/CMakeLists.txt`.

All three existing test methods are carried over: `testLogMacro`, `testLogPrintf`,
`testLogStringFormatter`.

--- WORKFLOW / CONVENTIONS ---

- One verified task per commit. Build and test green before moving to the next task.
- Commit scope for this assignment is `base` (log.h lives in GNbase), except the call-site
  sweep which uses `all`.
- The bulk call-site migration is done by script, never by hand-editing 1225 sites. The
  script must use paren matching and must skip comments and string literals: 53 call sites
  span multiple lines and ~15 have nested parentheses in the logger argument
  (`GN_ERROR(getLogger("GN.base.HandleManager"))(...)`), neither of which regex handles.
- After every scripted sweep run `env/bin/format-all-sources.py -d`, then re-run the
  scanner to confirm zero remaining trailing-call sites.
- Warnings are errors on all three compilers. Any new macro must compile clean as an
  unbraced if/for/while/switch body and in an if/else pair.
