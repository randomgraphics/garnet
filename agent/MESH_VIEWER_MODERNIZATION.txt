Replace the legacy mesh viewer with a format-neutral E2 application that loads and displays FBX, glTF, GLB, and STL scenes through FX2 and gpu2, while E2 owns world/snapshot composition and RDG2 owns frame ordering, submission, and presentation.

Do not use `GNgpu.h`, the legacy effect pipeline, `SampleApp`, `FatModel`, legacy engine mesh components, or the retired global input system. ## Design

### Module boundaries

The importer normalizes Assimp scenes into an immutable, format-neutral FX2 model asset containing hierarchy, transforms, primitives, material descriptions, textures, and bounds. FX2 owns graph-agnostic GPU resources and shading choices. E2 forms capture immutable model instances into visual moments and adapt those instances into FX2 draws. RDG2 retains the existing closed frame flow and owns gathered gpu2 submission and presentation. The tool remains a thin E2 client.

### Supported content

FBX, glTF, GLB, and STL are acceptance formats. glTF metallic-roughness maps to the PBR shading path. FBX material properties normalize into a general lit material. STL and incomplete assets use a deterministic default lit material. Geometry ownership is independent of shading so future inspection modes do not require re-importing assets.

### Environment lighting

The viewer defaults to image-based environment lighting, using the Asset Foundry Bad Salzbrunn skybox, irradiance cube, prefiltered radiance cube, and BRDF LUT through `fx2::SharedShaderConstants`. Imported metallic-roughness and general lit materials both consume the environment. A direct light may be enabled as optional fill, but it is not the primary lighting path. Missing material data uses a neutral rough dielectric material so FBX and STL remain realistically shaded.

### Input dependency

Interactive camera work consumes the new window-owned input API from `master` (or its eventual integration branch). This assignment will neither copy nor recommit that agent's changes. Asset loading, E2 integration, fixed-camera rendering, and headless tests proceed independently. The dependency is merged once its owner has committed and published a verified milestone.

### Camera interaction

The viewer exposes two explicit navigation modes. Arcball mode uses LMB drag to rotate the model/scene about its fitted pivot, RMB drag to translate that pivot parallel to the view plane, and wheel input to change eye-to-pivot distance multiplicatively (`distance *= exp(-wheelDelta * sensitivity)`). Bounds-derived minimum and maximum distances prevent clipping, inversion, and loss of the scene while retaining natural scale-independent zoom.

Fly-by mode rotates the camera about its current eye position with mouse motion and moves along camera-local axes using W/A/S/D. Movement is elapsed-time based, focus loss clears held state, and mode switches preserve a continuous camera pose without an unexpected jump.

### Dear ImGui integration

Dear ImGui is added as a shallow third-party submodule pinned to an audited upstream revision. A reusable Garnet backend translates ImGui draw data and platform input through gpu2 and the window-owned input API; it must not depend on legacy `GNgpu.h` or the effect pipeline. The mesh viewer owns its panels and uses the backend for scene hierarchy, selection/material inspection, environment controls, navigation-mode selection, and debug toggles. ImGui input capture suppresses camera controls so UI interaction cannot also move the scene.

### Test model corpus

Use existing project media and models already present in the repository as the primary integration corpus. In particular, exercise `media/boxes/boxes.fbx`, `media/model/R.F.R01/a01.fbx`, `media/asset-foundry/model/humanoid/humanoid.fbx`, `media/asset-foundry/model/humanoid/humanoid_ascii.fbx`, and `media/asset-foundry/model/DamagedHelmet/DamagedHelmet.gltf`. Use `media/asset-foundry/model/character/speeder-getaway-from-meshy-ai.glb` as the large real-world GLB stress case for hierarchy, materials, textures, memory use, framing, and rendering. Use Assimp's checked-out model corpus for compact GLB and STL coverage, including `glTF2/BoxTextured-glTF-Binary/BoxTextured.glb`, `glTF2/2CylinderEngine-glTF-Binary/2CylinderEngine.glb`, `STL/triangle.stl`, and one nontrivial ASCII and binary STL model.

Tests may add tiny synthetic fixtures only when exact deterministic assertions or malformed-input coverage cannot be expressed with an existing asset. Do not duplicate large media files under a test directory. Automated tests that rely on optional submodule content must report a clear skip when that content is unavailable; repository-owned media smoke tests are mandatory in a fully initialized checkout.

Dependency commits are merged once and retained with their original identity. Before integration, compare branch ancestry and patch identity to avoid duplicate commits.

--- WORKFLOW / CONVENTIONS ---

- FX2 must not depend on E2 or RDG2; RDG2 must not interpret models, materials, cameras, or worlds.
- E2 renders sealed visual moments and never reaches back into mutable forms during execution.
- Model parsing and immutable uploads occur outside the per-frame render path.
- Use public monolithic headers in clients, `AutoRef` ownership, and `RuntimeType::cast`.
- Keep all submodules shallow and use project build/test/format wrappers.
- Preserve other agents' commit ownership; merge dependency branches rather than copying their diffs.
- Each task is verified and committed independently before progress advances.
