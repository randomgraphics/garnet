# Assignment: Optimize GPU2 rendering many independent materials
---
## Goals
Reduce CPU rendering cost for 1024 independent materials while preserving per-draw
buffers and resource tables. Work toward the user's historical 400 FPS target.
---
## Design
Use collision-checked hash indexes for resource tables and draw configurations.
Visit only resources active in each barrier pass while preserving cross-pass state.
Reuse payload-local drawable argument storage and immutable descriptor snapshots.
Keep VMA host-visible allocations mapped across short-lived staging maps.

DrawParameters borrows geometry and resource tables by const reference; raster state
remains an inline value. draw() snapshots descriptions and retains GPU resources
before returning. Later edits/destruction of inputs cannot affect recorded draws.
GPU buffer contents themselves are not snapshotted. Both owning description types
retain move construction/assignment that transfers their array storage.

Independent recorders own mutable caches; no new shared recording locks. VMA/driver
internal synchronization remains. Concurrent submission or mutation of one recorder
is not covered. The experimental shared-mutex buffer pool was removed.

--- PROFILE RESULTS ---
Windows/MSVC RelWithDebInfo, RTX 4090, offscreen test mode, fixed physics timestep,
1024 dynamic bodies / 1026 draws, no material deduplication. Means from frames 4-60
of three runs, with logging but no sampler attached:
  Physics: 0.410 ms; draw recording: 5.395 ms; submission: 9.429 ms.
  Summed frame phases: 15.389 ms (runs 15.680 / 15.839 / 14.649 ms).
  Start-to-start interval including cleanup/logging: 15.660 ms, equivalent 63.9 FPS.
  Historical pre-index baseline: 55.137 ms; current phase time is 3.58x faster.
  Earlier rvalue-overload run: 13.129 ms; current phase time is 17.2% slower.
Historical comparisons are not same-session controlled A/B. Borrowed unique tables
now require a snapshot copy where rvalue inputs could transfer arrays; this is a
plausible contributor, not an isolated measurement of the API change.

Separate quiet run: 1000 main-thread wall-time samples, includes waits and sampling
overhead. Draw compilation/command recording: 25.7%; buffer creation: 9.6%; raster
snapshots/interning: 7.4%; resource collection: 6.9%; barriers: 4.0%.
CPU heap allocation/free leaves total 26.9%, overlapping those categories.
Buffer destructor appears in 3.6% of stacks, vmaDestroyBuffer in 2.9%; neither is a
vkFreeMemory-only measurement. Do not attribute all submission cleanup to buffers.
Remaining opportunity: CPU allocation, descriptor setup, and submission cleanup.
Temporary timers were removed and the profile executable rebuilt after capture.
